FAQ

Rules

Does Rusuban do anything before I write rules?

No. A repo without .rusuban/rules/*.md is observed only: its items show in the dashboard, no agent judges them, nothing merges, and nothing is written on GitHub on the agents' own initiative. Your own requests and tasks still run.

Where do the rules go?

In .rusuban/rules/*.md on the default branch of each repo, with an optional .rusuban/locks.json. Rusuban reads them nowhere else. See Writing rules.

Can a PR change the rules it is judged by?

No. Rules are read from the default branch only, and a PR that touches .rusuban/ never merges alone.

When does a rules change apply?

At the next read of the repo, 90 seconds by default, without a restart. Runs already at work keep the rules they started with. The change is journaled with its diff and flagged in your inbox.

What do the agents do where my rules say nothing?

They ask you on a card. When several cards ask the same, they propose the rule that would answer them, under Rules & settings. See Writing rules.

How do I try rules without risk?

Keep the merge switch paused: agents act as the rules say, and nothing merges until you arm it. A repo without rules is only read. rusuban start --dry goes further: the dashboard reads and shows, and starts no agent.

Merges

Can an agent merge?

No. Only the server merges, after its gates, on the exact head it checked.

Why did a PR not merge?

Its node shows the first gate that stops it, and lists them all once unfolded. Common reasons: merges are paused, it was judged not to merge alone, a lock, CI not green yet, or GitHub refused the merge.

How do I merge a PR the locks stop?

Pick its card's merge option: the server merges that head once CI, threads and conflicts allow (see merge orders). Or merge it yourself on GitHub, and Rusuban flags it as a merge it did not make.

My branch requires an approving review. Can the server merge?

Not on its own: GitHub refuses, the refusal goes on a card, and that head is not tried again. The approval bypass lets the server merge with --admin in a project, after it checks the branch's other rules.

How do I stop everything?

  • The switch in the dashboard's header pauses the server's merges in every project, the merge orders you give on cards included: they wait until it is armed again.
  • The Agents view stops a run.
  • rusuban project remove <id> stops a project; its files stay. While one of its runs waits or works, the command is refused.

Your machine and accounts

What runs on my machine, and where?

Headless claude -p sessions, on the model and under the host profile you chose. The judge, the coordinator and tasks work in ~/.rusuban/scratch/<project>/, unless a task names its own folder. Each worker gets a worktree of Rusuban's own clone of the repo, never your checkout. Anything else it makes goes in a work folder of its own, in ~/.rusuban/work/ unless rusuban work-root names another. Both are removed when it ends or stops.

Whose Claude plan do the agents use?

Yours: they run on your claude login, within its usage limits. A run that hits a limit waits for the reset, and the dashboard says until when.

Who do the agents act as on GitHub?

You. They use your gh login, so their comments and PRs appear under your account.

Where is the state?

In ~/.rusuban/ (RUSUBAN_HOME overrides it), never in your repos.

Can several people share an instance?

No. An instance is one person's, and every card shows in its owner's inbox. A card can name another GitHub login, and then says so.

Where do tasks that are about no repo go?

In a project without a repo: rusuban project create publications --title Publications, then give each task project: publications. The project holds their runs and conversations, and its page shows them where a graph would be. Nothing is read, judged or merged on GitHub for it.

Each project's page shows only its own tasks, runs and conversations; the inbox gathers every project's cards.

Can I use another forge, or another agent?

No. GitHub only, through gh, and Claude Code only.

In what language do the agents write?

Your rules may be in any language. Cards, the journal and final answers are in English; messages on GitHub follow your rules.
