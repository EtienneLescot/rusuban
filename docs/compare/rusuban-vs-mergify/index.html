Rusuban vs Mergify

Both merge pull requests without a person, once conditions you set hold. Mergify is a hosted merge queue and workflow automation: you write conditions in .mergify.yml, and it merges when they hold. Its merge queue tests pull requests against the latest base branch first. Rusuban runs on your machine and has Claude Code judge each issue and pull request against plain-text rules, then merges what those rules allow, behind locks its server checks. Mergify is the better choice for teams that merge many pull requests a day and need a merge queue.

This page is published by the Rusuban project. The details on Mergify come from Mergify's documentation and pricing page, checked in November 2026. The sources are listed at the end.

What both do

  • Merge on their own when the conditions hold, with checks green on the pull request.
  • Keep the conditions in the repo. Mergify reads .mergify.yml. Rusuban reads .rusuban/rules/ and .rusuban/locks.json.
  • Rebase a pull request that falls behind.
  • Take orders. Mergify answers @Mergifyio commands in comments. Rusuban takes your answer on a card, such as a merge order for one head.

Where Rusuban differs

A judgment, then locks

Some rules need someone to read the diff: "a bug fix with a test merges alone; a new dependency comes to me". Rusuban has Claude Code judge each pull request against rules like these, for its exact head. Then its server checks what no model is asked about: CI green on that head, no open review thread, your locked paths and size limits. See auto-merge behind locks.

Issues too

Rusuban judges every issue as well: it closes a duplicate, asks a reporter for what is missing, or has a worker write a fix and its test, as your rules say. See issue and PR triage.

Your decisions on cards

What your rules keep for you comes as a card, in one inbox for all your projects, answered in the dashboard or on your phone.

Local and open

Rusuban runs on your machine and its code is MIT-licensed. It has no server of its own.

When Mergify is the better choice

  • You merge many pull requests a day. A merge queue tests them against the latest base branch, so a green PR does not break the branch once merged.
  • You want merges decided by conditions alone, with no model reading the pull request.
  • You need its workflow actions, such as backports to release branches.
  • You keep no machine on. Mergify is a hosted service.

Getting started

  1. Install Rusuban: npm install -g rusuban, then rusuban init.
  2. Write which pull requests may merge alone in your rules, and what the server must check in locks.json. See Locks.
  3. Keep merges paused while you read the first judgments, then arm the switch.
